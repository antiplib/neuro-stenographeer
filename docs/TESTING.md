# Проверки версии 0.2

Android assembleDebug: BUILD SUCCESSFUL. Kotlin и C++ собраны для ARM64. APK signature проверена. Все четыре модели внутри APK сверены по SHA256. В манифесте нет INTERNET. Проверена компиляция JNI с новым контрактом.

Новая версия не запускалась на реальном телефоне: подключённых устройств нет. WER/DER/RTF на пользовательских разговорах не измерены. Проверка прокрутки и визуальной темы на реальном устройстве остаётся необходимой. Дообучение не проводилось: пользователь сообщил, что размеченного набора пока нет.

Для регрессии на устройстве: установить поверх 0.1 → проверить автоматическую замену моделей → открыть старую историю → обработать новый русский диалог с «Авто» и известным числом участников → прокрутить весь длинный результат → экспортировать JSON → повторить в авиарежиме. Особенно проверить короткие реплики, одинаковые голоса, тишину и перебивания.

## Версия 0.3

Добавлены C++ регрессии для перекрывающихся голосовых интервалов, тишины, музыкальных пометок и повторяющихся последовательностей токенов. Обычные предложения со словом «музыка» и короткие реальные повторы сохраняются. Тесты прошли. На пользовательской записи улучшение WER/DER пока не измерялось.

## Версия 0.4

Новый тест transcript_preservation проверяет сохранение полного UTF8 текста без найденного спикера, при пустой диаризации, схлопнувшихся временных метках, реальных повторах и скобочных пометках. Он проверяет используемую native-функцию preserveSegment. Тест пройден. Старые фильтры 0.3 остаются только в файле исторических тестов, но pipeline 0.4 их не вызывает. Это регрессии кода, не end-to-end измерение полноты распознавания пользовательского файла.

## Версия 0.5

C++ speaker_alignment проверяет смену спикера внутри предложения, неоднозначную одновременную речь, объединение пересекающихся интервалов, отсутствие временных меток и точное сохранение исходной UTF8 строки. Все четыре C++ теста прошли.

Kotlin ResamplerTest измеряет DFT-проекции: при 48→16 кГц амплитуда полезного тона 4 кГц — 1.00050, паразитного тона 6 кГц от входного 10 кГц — 0.000466 (около −67 дБ). Также проверены длина/хвост выходного сигнала и частоты входа 8, 16, 44.1, 96 и 192 кГц. Это синтетические проверки DSP, не измерение DER/WER на диалогах.

Повторить: скомпилировать BandLimitedResampler.kt вместе с tests/ResamplerTest.kt обычным kotlinc и запустить ResamplerTestKt.

## Версия 0.8

Шесть C++ регрессий прошли. Новый timing_repair проверяет ограниченное опорными метками восстановление отсутствующих timestamps, сохранение двух спикеров, точное сохранение UTF8 текста, неизменность существующих меток и отказ от полностью выдуманного выравнивания без опор. Сценарии с полностью неизвестным голосом продолжают сохранять текст. Интерполяция может ошибаться на перебиваниях; DER на пользовательском аудио не измерен.
